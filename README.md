# Микродизайн · новый магазин

Отдельное Django-приложение. `../catalog` и `../site-mirror` не изменяются.

## Запуск в Docker (рекомендуется для локальной разработки)

Из папки `microdesign-store`:

```bash
docker compose up --build -d
docker compose logs -f init web
```

Сайт: http://localhost:8000. Админка: http://localhost:8000/admin/.
Первый запуск дождётся PostgreSQL, применит миграции и импортирует страницы/каталог. Если уже есть локальные WebP в `media/`, они используются повторно; иначе первый импорт займёт несколько минут. Исходный `../catalog` подключается только к задаче импорта и только для чтения. `site-mirror` не подключается.

Создать администратора (после завершения `init`):

```bash
docker compose exec web python manage.py createsuperuser
```

Проверить приложение на PostgreSQL:

```bash
docker compose exec web python manage.py test
```

Остановка с сохранением данных:

```bash
docker compose down
```

PostgreSQL хранится в отдельном Docker volume, фотографии — в локальной `media/`. SQLite-база остаётся отдельной и не изменяется: учётные записи и заказы из неё автоматически в PostgreSQL не переносятся. Повторный импорт сохраняет редакторские изменения в PostgreSQL.

Изменения исходников видны сразу благодаря bind mount и Django autoreload. Если порт 8000 занят: `WEB_PORT=8001 docker compose up -d`. На Linux с UID/GID, отличными от 1000, передавайте `LOCAL_UID=$(id -u) LOCAL_GID=$(id -g)` перед командами Compose, которым нужен запуск контейнера. Платежи в этом локальном окружении отключены. Это конфигурация разработки, не production-развёртывание.

## Запуск без Docker

```bash
uv venv .venv
uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python manage.py migrate
.venv/bin/python manage.py import_pages
.venv/bin/python manage.py import_catalog ../catalog
.venv/bin/python manage.py createsuperuser
.venv/bin/python manage.py runserver 127.0.0.1:8000
```

Открыть http://127.0.0.1:8000, админка — http://127.0.0.1:8000/admin/.
В текущем рабочем каталоге зависимости установлены, каталог уже импортирован. База SQLite и производные WebP находятся локально, в Git не включены. Исходный каталог необходим только для первоначального импорта. После импорта приложение работает независимо от него.

## Что работает

- Каталог из базы: 26 разделов, поиск по названию и артикулу, фильтры масштаба/наличия, сортировка, пагинация.
- Карточка: галерея, описание, цена, масштаб, артикул, товары раздела.
- Админка: создание/редактирование товаров, загрузка нескольких изображений, подписи и порядок, категории, статические страницы и заказы.
- Регистрация, вход/выход, корзина в серверной сессии, оформление и история собственных заказов, трек-номер.
- Серверные снимки цен в заказе, защита повторного оформления, CSRF.
- Адаптер Робокассы: URL оплаты, подпись, проверка суммы, атомарное идемпотентное подтверждение ResultURL. Возврат покупателя сам по себе не подтверждает оплату.
- Контакты, все опубликованные банковские реквизиты, доставка, оплата и текст о компании перенесены из оригинала. HTML-источники сохранены в `docs/source-*.html`, ссылка на исходную оферту сохранена.

## Работа с товарами

В админке откройте «Товары» → «Добавить». Заполните раздел, название, slug, цену, масштаб, описание и артикул. Добавьте фотографии в таблице под карточкой, задайте порядок: первая фотография станет обложкой. Флаг «Опубликован» управляет видимостью, «На главной» — подборкой. Отметьте «Наличие подтверждено», чтобы разрешить добавление в корзину.

Остатки отсутствуют в исходном архиве: импорт не придумывает наличие. Для 9 карточек отсутствует цена; они показываются с ценой по запросу. Складской количественный учёт ещё не реализован: флаг доступности — ручной.

Повторный импорт сохраняет редакторские изменения. `--refresh` явно перезаписывает исходные поля и связи фотографий. `--originals` копирует оригиналы вместо WebP; обычный импорт создаёт WebP до 1600 px. Очень большие сканы сохраняются оригиналами без декодирования. Не запускайте два импорта одновременно. Данные SQLite предназначены для локальной разработки; на сервере используйте PostgreSQL.

## Проверки

```bash
.venv/bin/python manage.py check
.venv/bin/python manage.py test
.venv/bin/python manage.py makemigrations --check --dry-run
```

Тесты проверяют поиск, HTTP/CSRF, корзину, цены на сервере, доступ к заказам, повторные уведомления и поддельные подписи Робокассы, безопасный повторный импорт. Все 12 тестов проверены на SQLite и PostgreSQL в Docker. Живой платёж ещё не проверялся.

## Перед запуском продаж

Это локальная первая версия, не готовый к приёму платежей production-магазин. Подробности: [архитектура](docs/ARCHITECTURE.md) и [план запуска](docs/LAUNCH.md). Ключи и настройки берутся из переменных окружения; `.env.example` — образец, автоматической загрузки `.env` нет.
